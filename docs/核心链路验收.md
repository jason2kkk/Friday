## 验收前提

- 使用稳定签名的 Friday Debug 构建。
- 后端 `npm run doctor` 返回上游可用，或明确使用 `FRIDAY_DICTATION_MODE=mock`。
- 麦克风和辅助功能权限已经按测试场景授予或拒绝。
- 测试内容不得包含真实密码、客户隐私或生产凭证。

## 必测路径

1. 聚焦输入框，单独轻按并松开 `Fn`，正常说话，再轻按一次结束；最终文字只写入原目标。
2. 写入后立即按 `Cmd + Z`；内容恢复为 Friday 写入前的状态。
3. 开始录音后切换焦点；Friday 不向新的未确认控件误写，并保留结果。
4. 开始录音后关闭目标应用；Friday 展示完整结果供复制。
5. 无输入框时完成录音；Friday 仍完成处理并展示结果。
6. 在密码框触发；Friday 不写入密码控件。
7. 录音期间按 `Esc`；录音停止、音频从内存清除、不会创建后续模型响应。
8. 处理期间断网；本轮音频保留，只在用户显式重试时重新调用。
9. 写入期间制造焦点变化；文字保留，剪贴板不被静默覆盖。
10. 只录制静音和背景底噪；不创建 Realtime 会话，显示“未收听到声音”。

## 通过标准

- 六个目标应用不存在已知误写场景。
- TextEdit、备忘录和 Safari 的写入与系统撤销全部通过。
- 所有失败路径都保留音频或最终文字中的一种可恢复资产。
- 失败不会自动无限重试，也不会在无用户动作时额外创建 Realtime 会话。
- 真机结果记录日期、系统版本、Friday 构建和失败证据。
