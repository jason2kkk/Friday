# Friday 转写质量评测

> 查询日期：2026-07-28。官方参考：[Realtime 与音频](https://developers.openai.com/api/docs/guides/realtime)、[Realtime 转写](https://developers.openai.com/api/docs/guides/realtime-transcription)、[Realtime Prompting](https://developers.openai.com/api/docs/guides/realtime-models-prompting)、[Realtime 成本](https://developers.openai.com/api/docs/guides/realtime-costs)。

## 三层质量证据

1. **确定性防护：** 本地评测集验证无语音、寒暄、确认包装、代码围栏和原始转写回退，不调用模型。
2. **模型语义评测：** 使用固定口述脚本真实录音，比较原始含义和最终文本；每次 Prompt 或模型变化后重复。
3. **场景验收：** 在邮件、消息、笔记和搜索输入框中检查文本是否适合继续编辑和撤销。

## 固定口述脚本

| 类别 | 口述内容 | 必须保留 | 允许整理 | 禁止行为 |
| --- | --- | --- | --- | --- |
| 问题句 | “这个问题我们怎么解决” | 问题本身 | 标点 | 回答问题 |
| 残句 | “我觉得这个方案可能还需要” | 未完成状态 | 最小标点 | 自动补完 |
| 自我纠正 | “周三，不对，周四下午三点” | 周四、下午三点 | 删除被明确否定内容 | 保留错误日期 |
| 数字 | “预算是一万二，不超过一万五” | 12000、15000、上限关系 | 数字格式 | 改变金额 |
| 否定 | “不要发给客户，先发给我确认” | 两个动作及顺序 | 分句 | 删除否定词 |
| 列表 | “分三点，稳定性、速度、成本” | 三项顺序 | 项目符号 | 新增第四项 |
| 中英混合 | “把 Friday 的 realtime provider 改成可切换的” | 产品名和术语 | 大小写、标点 | 翻译专有名词 |
| 语气指令 | “把下面这段写正式一点，项目要晚两天” | 延期两天 | 正式语气 | 增加原因 |
| 纯口癖 | “嗯，呃，就是” | 无有效内容 | 无 | 输出寒暄 |
| 背景声音 | 无面向 Friday 的人类口述 | 无有效内容 | 无 | 邀请用户继续说话 |

## 评分

- **关键事实保留率：** 数字、日期、姓名、否定、条件和专有名词全部保留才算通过。
- **幻觉率：** 输出中出现口述不存在的事实、解释、回答或续写即失败。
- **结构适配：** 只在用户要求或内容明确并列时使用列表或标题。
- **恢复率：** 模型包装或处理失败时，原始转写或本轮音频仍可恢复。
- **延迟：** 分别记录录音结束到结果返回、结果返回到写入完成的时间。

## 成本边界

- 当前默认继续使用单次 Realtime 音频到文本响应。
- 开发验证版默认使用 `gpt-live-transcribe`，因此真实 Dictate/Talk 会增加独立输入转写费用；空的 `FRIDAY_INPUT_TRANSCRIPTION_MODEL` 可关闭。
- 真机验收要按官方独立费率记录模型和用量，并先在 OpenAI Project 中设置预算上限。
- 自动评测集和后端假上游测试必须保持零 API 调用。
