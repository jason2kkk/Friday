# Friday 文档入口

## 权威文档

- [产品路线图](产品路线图.md)：产品定位、阶段目标、用户故事、验收条件和未决问题。
- [项目结构](项目结构.md)：当前仓库目录、逐文件职责、源码文件头约定和本地产物边界。
- [架构概览](架构概览.md)：用架构图和流程图说明 Friday 的整体结构、三条产品路径、记忆策略、异步 Work 和关键取舍，建议首先阅读。
- [技术架构](技术架构.md)：Friday 的数据契约、状态机、存储边界、模块依赖和渐进迁移顺序。
- [交互架构](交互架构.md)：常驻灵动岛、展开矩形、岛内确认和后台结果的产品职责与交互流程。
- [Qwen Audio Agent 架构研究](Qwen%20Audio%20Agent%20架构研究.md)：基于固定提交的源码级复核、可借鉴边界和不应照搬的部分。
- [LiveKit Talk 技术验证计划](LiveKit%20Talk%20技术验证计划.md)：记录已完成的零费用 Stage 0 Runtime 契约，以及尚未获批的 SDK、真实语音、费用与采纳门槛；不代表已经接入 LiveKit 或改善了语音体验。
- [工程协作规范](工程协作规范.md)：产品负责人和 Codex 的协作方式、审批边界、交付标准和沟通格式。
- [编程 Agent 规范](编程Agent规范.md)：源码文件头的详细格式，以及新增文件或职责变化时的结构同步规则。
- [Issue 与 PR 工作流](Issue与PR工作流.md)：Issue 拆分、分支命名、PR 审查、合并和 Agent 外部操作边界。
- [工程问题与复盘](工程问题与复盘.md)：记录复杂问题的现象、证据、假设、根因、解决方案、验证和可复用经验。
- [核心链路验收](核心链路验收.md)：跨应用写入、撤销、失败恢复和真机验收矩阵。
- [转写质量评测](转写质量评测.md)：固定口述脚本、质量指标、原始转写和成本边界。
- [AGENTS.md](../AGENTS.md)：Codex 在仓库内执行代码任务时必须遵守的工程规则。

## 文档优先级

1. 用户当前消息和明确确认的决策。
2. `AGENTS.md` 中的工程安全规则。
3. `编程Agent规范.md` 中的源码说明与结构同步流程。
4. `Issue与PR工作流.md` 中的开发记录和审查流程。
5. `工程问题与复盘.md` 中已验证的问题证据和根因记录。
6. `产品路线图.md` 中的当前产品阶段和验收条件。
7. `架构概览.md` 中的系统边界和核心设计决策。
8. `技术架构.md` 中的数据契约、依赖方向和迁移顺序。
9. `交互架构.md` 中的用户界面职责和交互流程。
10. `工程协作规范.md` 中的协作流程。
11. 架构研究、README、源码注释和历史讨论。

如果文档之间冲突，先指出冲突，不自行选择一个版本继续扩大实现范围。

## 文档维护

产品行为、阶段目标和验收条件变化时，先更新路线图，再改代码。
技术方案、供应商、权限或数据边界发生实质变化时，在路线图的决策记录中留下日期和理由。
复杂问题的调查过程、失败实验、根因、修复和验证同步到《工程问题与复盘》；调查中条目不能写成已解决事实。

文档面向两类读者：`架构概览.md` 应让不了解项目的人在十分钟内理解设计；`技术架构.md` 应让开发者能够据此实现和评审。详细源码研究只作为证据，不替代项目自己的架构说明。

仓库自动质量门禁使用 `../scripts/verify.sh`；真实麦克风和跨应用输入验收仍按《核心链路验收》执行。
